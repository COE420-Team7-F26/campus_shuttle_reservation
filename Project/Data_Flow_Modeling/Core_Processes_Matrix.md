#Core Processes Matrix
| Process No. and Name | Input Data | Output Data | Rules |
|---|---|---|---|
| P1 –1.0 Manage user authentication | Login/logout requests from students, shuttle drivers, transport administrators, and IT staff; user credentials and roles from D1 User Accounts. | Session status; session information stored in D1; system error logs returned to IT staff upon request. | Validate login credentials against D1 before creating a session. Assign access according to the stored user role. Reject invalid login attempts. End the active session when the user logs out. Only authorized IT staff may request system error logs.|
| P2 –2.0 Manage shuttle information | Shuttle information requests from students; shuttle information updates from the transport administrator; existing routes and schedules from D2 Shuttle Information. | Shuttle schedules sent to students; update confirmations sent to the transport administrator; updated shuttle information stored in D2. | Retrieve the relevant routes and schedules when a student requests shuttle information. Only the transport administrator may modify shuttle information. Validate that updated trip details are complete and that departure times are valid before saving them. Return confirmation after a successful update.|
| P3 –3.0 Manage reservations | Booking/cancellation requests from students; seat availability from D3 Reservations/No shows.| Booking/cancellation status sent to students; booking records stored in D3; passenger lists sent to shuttle drivers; booked shuttle information sent to Process 4.0.| Accept bookings only when seats are available and the student is permitted to reserve. Prevent duplicate bookings for the same student and trip. Allow students to cancel their own active reservations. Update reservation records and seat availability after successful bookings or cancellations. Generate passenger lists from active reservations.|
|P4 –4.0 Track shuttle and send notifications| Live location data and shuttle delay reports from drivers; trip updates/departure information; shuttle details from D2; booked shuttle information from Process 3.0.| Live shuttle location and delay/departure alerts sent to students; updated location and status stored in D2.| Associate each location or delay update with the correct shuttle and trip. Use location data supplied by the driver’s device to update the shuttle’s displayed position. Record changes to the trip status. Notify students with reservations for the affected trip when a delay or departure change occurs.|
|P5 –5.0 Manage No-Show Reports| Driver no-show reports submitted by students; student no-show reports submitted by drivers; existing no-show records from D3; no-show decisions from the transport administrator.| No-show reports sent to the transport administrator; reports and decisions stored in D3.| Link each report to the relevant trip and reported person. Check student no-show reports against the trip’s reservation records. Store reports for administrator review. Only the transport administrator may decide whether to suspend or dismiss a reported case. Record the decision and apply any approved suspension according to the project’s no-show policy.|
